# Slowline Browser

Небольшой Android-браузер на Java + системный Chromium WebView. Цель версии 0.1 — аккуратный нейтральный интерфейс, работа при медленном соединении, локальная кэш-копия только текущей страницы и базовая защита от трекеров.

**Статус:** экспериментальный прототип. Репозиторий содержит сборочную конфигурацию GitHub Actions; сборка в Android SDK внутри среды подготовки не запускалась, поэтому первый build в GitHub Actions — обязательный этап проверки, а затем нужны испытания на реальных Android 16/17 и сети 2G.

## Возможности

- Android 16/17: `compileSdk 37`, `targetSdk 37`, минимальная версия Android 8.1/API 27.
- WebView/Chromium выполняет рендеринг, JavaScript, историю навигации и обычные формы.
- Тонкий индикатор загрузки: процент самого WebView, число уникальных URL, суммарный размер ресурсов с известным `Content-Length`, байты, прочитанные через сетевой слой, и объём, выданный из локального кэша.
- Изображения загружаются по умолчанию. Экономия достигается повторным использованием ресурсов текущей страницы, блокировкой списка трекеров и отсутствием предварительной загрузки страниц самим приложением. Изображения можно отключить вручную.
- Одностраничный дисковый кэш: при переходе на другой верхнеуровневый URL старые записи удаляются; ресурсы текущей страницы хранятся между перезапусками приложения. Размер кэша ограничен примерно 128 MiB; главная HTML-запись может превысить лимит, если сама очень велика.
- Основной HTML, редиректы, отправка форм и динамические `fetch`/`XHR` обслуживаются Chromium/WebView напрямую: это сохраняет совместимость с поисковиками и JavaScript-heavy сайтами. Собственный дисковый кэш и возобновление `Range` применяются к подходящим статическим GET-ресурсам (CSS, JS, изображения, шрифты и медиа). Текущая версия не обещает возобновление произвольного главного HTML-документа, зато не подменяет ответ сайта обрезанным фрагментом.
- Длительный тайм-аут чтения для очень медленной сети; при обрыве сохранённый частичный ответ не очищается.
- Локальный список доменов аналитики/рекламы с возможностью отключить блокировку.
- Сторонние cookie по умолчанию запрещены; можно разрешить вручную. Это может ухудшить некоторые SSO/встроенные виджеты.
- Блокировка смешанного HTTP-контента, Safe Browsing, проверка TLS-сертификатов без кнопки «всё равно открыть», запрет файлового доступа из WebView, отказ в доступе к геолокации и веб-разрешениям по умолчанию.
- Загрузки файлов через системный DownloadManager, выбор файла для `<input type=file>`, копирование URL с удалением распространённых рекламных меток, очистка cookie/localStorage/истории/кэша.
- Пункт меню открывает системные настройки Android Private DNS. Это настройка DNS устройства, не встроенный прокси.

## Сборка в GitHub

1. Создай пустой репозиторий GitHub и загрузи содержимое ZIP в корень репозитория.
2. Дождись выполнения **Actions → Android build** (либо запусти workflow вручную).
3. В успешном workflow открой артефакт `slowline-browser-debug-apk` и скачай `app-debug.apk`.

Файл создаётся по адресу `app/build/outputs/apk/debug/app-debug.apk`. Это debug APK для тестирования, не подписанный release-пакет для публикации в магазине.

Локальная сборка с JDK 17, Android SDK API 37 и доступом к Maven Central:

```sh
./gradlew assembleDebug
```

В проекте используется Gradle bootstrap-скрипт, который применит установленный Gradle 9.6.0 либо загрузит официальную дистрибуцию Gradle. Android Studio также можно использовать для открытия корневой папки проекта.

## Важные технические границы

### Индикатор загрузки и статистика трафика

Полоса показывает прогресс главного документа Chromium, а не готовность всех асинхронных операций на сайте. Скорость и входящие байты показываются по счётчику сетевого трафика UID приложения, который включает запросы самого Chromium; размер и число ресурсов доступны только для запросов, которые наблюдает слой перехвата. Поэтому показатели полезны для контроля 2G, но не являются точным размером всех ресурсов веб-страницы.

### Продолжение прерванной загрузки

Для перехватываемых статических GET-ресурсов браузер сохраняет полученные байты и пробует запросить остаток через HTTP Range при следующем запросе. Это невозможно гарантировать для любого сайта: сервер может не поддерживать Range, изменить ресурс, не выдавать проверяемые валидаторы, отдавать `no-store`, динамически генерировать ответ или использовать нестандартный редирект. При отсутствии совпадающего валидатора браузер не склеивает разные версии. Неполный CSS/JS/изображение никогда не выдаётся как законченный HTTP 200: запрос передаётся Chromium. Главный HTML и формы обслуживаются самим WebView; продолжение байтов главного HTML в этой версии не гарантируется.

### Совместимость сайтов

Чтобы не ломать Chromium-навигацию, нестандартные методы, ссылки с перенаправлением и пользовательские `Range`-запросы остаются под управлением WebView. Перенаправленный документ может пройти через нативный сетевой путь и не получить продолжение главного HTML-ответа при первой загрузке. Также отдельные сайты могут зависеть от клиентских TLS-сертификатов, third-party cookies, service worker, WebAuthn или popup-окон; такой прототип не заменяет полноценный браузер на базе собственного Chromium.

### Приватность и блокировки

Это **не анонимайзер**. Сайты по-прежнему видят IP-адрес подключения и могут применять fingerprinting. Оператор сети может видеть сетевые метаданные; системный Private DNS в основном защищает DNS-запросы и не гарантирует обход блокировок по IP, SNI, DPI или самим адресам сайтов. Встроенных VPN, Tor, прокси, подмены IP или гарантированного обхода блокировок нет. Список блокировки локальный и не исчерпывающий; возможны ложные срабатывания. HTTPS-сертификаты не обходятся; HTTP оставлен доступным ради совместимости со старыми/минималистичными сайтами.

## Рекомендуемая проверка перед реальным использованием

- Сборка debug APK на GitHub Actions с API 37.
- Android 16/API 36 и Android 17/API 37; Samsung One UI 9, если доступно устройство.
- Медленный Wi‑Fi/эмуляция 2G: обрыв в середине HTML, CSS, изображения и JavaScript; затем reload и проверка запроса Range в логах тестового сервера.
- Сайт с `ETag`/`Last-Modified`, сайт с `Accept-Ranges: bytes`, сайт без Range и сайт с `Cache-Control: no-store`.
- Редиректы 301/302, вход через cookie, форма POST, скачивание файла, страницы с service worker и медиаплееры.
- Проверка, что после перехода на новый адрес файлы предыдущей страницы удалены; проверка очистки cookie и WebStorage.
